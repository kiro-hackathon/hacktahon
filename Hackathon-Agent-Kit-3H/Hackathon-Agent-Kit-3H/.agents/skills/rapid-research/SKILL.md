# Research fast, then ship

1. Ask: "What decision will this information change?" If none, **skip research**.
2. Search at most three targeted questions: existing alternatives and common user pain; minimum viable implementation; blocking API/permission constraints.
3. Prefer original official docs for specs, dated source for volatile details. Record source title/link/date only if visited. Never invent sources, recent pricing, or API access rights.
4. Output a **6-line research note** to `.hackathon/BRIEF.md`: competitors (max 2), borrowed good pattern, differentiation, chosen stack rationale, risk, links.
5. Limit to five minutes; decide with incomplete information when sensible. If no browsing/search tool, state `Online research: NOT AVAILABLE` and proceed from known requirements.
6. Avoid installing research tooling or browsing broad inspiration galleries during the sprint.

**Product preference:** identifiable user pain + immediate interactive result beats market-size slides.
